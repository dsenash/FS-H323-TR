# mod_aa_h323_tr — H.323 trunk between FreeSWITCH and Avaya Communication Manager

[Русская версия](README.ru.md)

A built-in FreeSWITCH module written in pure C (no Python, no third-party libraries) that connects FreeSWITCH
to Avaya Communication Manager (CM) as an H.323 trunk. It is free software: no licensing, no trial, no limits
(MIT license, see [LICENSE](LICENSE)).

## What has been verified

Verified on a test stand (FreeSWITCH installed from packages, CM at 192.168.0.193):

- building and installing with `install.sh`, loading the module into FreeSWITCH;
- accepting H.225 TCP connections on a dedicated port (1722 by default);
- the `aa_h323_tr status` command;
- the service STATUS exchange between the module and CM; the CM trunk group goes `in-service`
  (provided CM media resources are up, see "Maintenance").

Everything else is still in development; only verified parts are described here.

## Architecture

```
 FreeSWITCH + mod_aa_h323_tr                                 Avaya CM
 ┌─────────────────────────────────────┐
 │ service connection                  │ ── TCP, H.225 ──▶ trunk[].ip:port (1720)
 │ listener local.ip:h225_port         │ ◀── TCP, H.225 ── connections from CM
 └─────────────────────────────────────┘
```

`mod_aa_h323_tr.so` consists of these layers:

| File | Purpose |
|------|---------|
| `fs/mod_aa_h323_tr.c` | FreeSWITCH glue: module load, the `aa_h323_tr` endpoint, the `aa_h323_tr` API command, XML config reading |
| `aa_tr_engine.c/h` | pthread-based engine: H.225 listener, service connections to trunks, trunk state table |
| `aa_tr_msg.c/h`, `aa_tr_tpl.h` | building and parsing Q.931/H.225.0/H.245 messages from templates taken from real CM traffic captures |
| `aa_tr_config.c/h`, `aa_json.c/h`, `aa_smap.c/h` | JSON configuration parsing |

The message templates (`aa_tr_tpl.h`) are generated by `tools/gen_tr.py` from traffic captures (the captures are not published; the generated files are committed).

**Listener.** The module listens on TCP `local.ip:local.h225_port`. If the port is busy the module still loads:
a warning is logged, `aa_h323_tr status` shows `NOT LISTENING (...)`, and bind is retried every 5 seconds.
Port 1720 is usually taken by the sibling module `mod_aa_h323`, so 1722 is the default.

**Service connection.** For every trunk in `trunk[]` the module itself opens a TCP connection to the CM `ip:port`
and reports availability over it: right after connecting it sends a Q.931 STATUS with the global call reference
(cause 31, then 16), and afterwards STATUS cause 16 every 7.6 seconds. STATUS messages from CM (cause 47 = out of service;
31 and 16 = in service) update the trunk state shown by `aa_h323_tr status`. If the connection drops it is re-established after 5 seconds.

**Configuration** is two files in the FreeSWITCH configuration directory:

- `autoload_configs/aa_h323_tr.conf.xml` — path to the JSON file (`config-json`), dialplan and context for inbound calls, optional `local-rtp-ip`;
- `aa_h323_tr/aa_h323_tr.json` — the main configuration (example: `config/aa_h323_tr.example.json`):

| Key | Meaning |
|-----|---------|
| `local.ip` | IP of **this** FreeSWITCH server (the module listens on it and announces it to CM) |
| `local.h225_port` | H.225 listen port; optional, default 1722 |
| `identity.product`, `identity.version`, `identity.display` | how the module presents itself to CM |
| `trunk[].name` | trunk name |
| `trunk[].ip`, `trunk[].port` | CM address and port (default 1720) |
| `trunk[].codec` | `PCMA` (G.711 A-law) or `PCMU` (G.711 mu-law) |
| `trunk[].lines` | number of lines (default 100, 0 = unlimited) |
| `trunk[].in_number_rules[]` | inbound number rewrite rules `{match, strip, add}`; the first matching rule wins |

## Requirements

- FreeSWITCH with module development headers (`freeswitch-dev` or a from-source install);
- `gcc`, `make`, `pkg-config`, `awk`; root for installation.

## Deployment with install.sh

```
cd mod_aa_h323_tr
sudo ./install.sh
```

The script runs seven steps: build `fs/mod_aa_h323_tr.so`; install the module; install the XML config and dialplan
(only if they do not exist yet); create/edit `aa_h323_tr.json`; add `mod_aa_h323_tr` to `modules.conf.xml`;
check that the dialplan is included; reload the module in the running FreeSWITCH and print `aa_h323_tr status`.

It asks for this server's IP (`local.ip`) and the listen port (`local.h225_port`), offering the current values.
Unattended:

```
sudo AA_TR_LOCAL_IP=192.168.0.6 AA_TR_PORT=1722 ./install.sh
```

Re-running is safe: `local.ip` and `local.h225_port` are overwritten, the rest of the JSON (trunks, number rules) is left alone.

After installing, put the real trunks into `aa_h323_tr.json` (`trunk[]`: `ip`, `port`, `codec`, `lines`, number rules) and reload the module:
`fs_cli -x "reload mod_aa_h323_tr"`.

## Deployment with the deb package

The `mod-aa-h323-tr` package is built on a machine that has FreeSWITCH with headers installed (the module is compiled against it):

```
cd mod_aa_h323_tr
packaging/deb/build-on-target.sh
sudo apt install ./mod-aa-h323-tr_1.0.0_amd64.deb
```

`build-on-target.sh` variables (all optional): `FS_SRC` — FreeSWITCH source directory, `FS_CFLAGS`/`FS_LIBS` — flags set by hand,
`VER`, `ARCH`, `NOBUILD=1` — package an already built `fs/mod_aa_h323_tr.so`. A ready `.so` can also be packaged directly:
`packaging/deb/build.sh fs/mod_aa_h323_tr.so`.

On installation `postinst` runs `/usr/sbin/mod-aa-h323-tr-setup`, which:

- locates FreeSWITCH (`FS_PREFIX`, or `FS_MODDIR` and `FS_CONFDIR`, or autodetection; values can be stored in `/etc/default/mod-aa-h323-tr`);
- copies the module into the module directory;
- creates `aa_h323_tr.conf.xml`, the dialplan and `aa_h323_tr.json` **only if they do not exist** (existing administrator files are never overwritten);
  in a new JSON it sets `local.ip` from the default route (override with `AA_TR_LOCAL_IP` and `AA_TR_PORT`);
- adds `mod_aa_h323_tr` to `modules.conf.xml`.

If FreeSWITCH is not found the package is still installed; run the setup later:
`sudo FS_PREFIX=/usr/local/freeswitch mod-aa-h323-tr-setup`.

Removal: `apt remove mod-aa-h323-tr` unloads and removes the module but keeps the administrator's configuration; `apt purge` removes that too.
After installing or removing, restart FreeSWITCH or run `fs_cli -x "load mod_aa_h323_tr"`.

## CM setup

In the CM signaling group bound to the trunk:

- `Far-end Node Name` — the node with the FreeSWITCH server IP;
- `Far-end Listen Port` — `local.h225_port` (1722 by default).

## Maintenance

- Status: `fs_cli -x "aa_h323_tr status"` — build, config path, listener (`NOT LISTENING` if the port is busy),
  and per trunk: address, codec, lines, `in service` or `OUT OF SERVICE`.
- Changing configuration: edit `aa_h323_tr.json`, then `fs_cli -x "reload mod_aa_h323_tr"`.
- Upgrading: run `sudo ./install.sh` again or install the new deb package. If the new build was not picked up after `unload`/`load`,
  run `systemctl restart freeswitch`.
- Log: the module writes to the FreeSWITCH log (`/var/log/freeswitch/freeswitch.log`); search for `aa_tr` / `aa_h323_tr`. The `logging` block of the JSON is read but not used yet.
- Port 1720 is busy: it is normally taken by `mod_aa_h323`; set another `local.h225_port` (1722 by default) and use the same port in CM.
- CM trunk group members stay `out-of-service-NE` while the signaling group is `in-service`: check the CM media resources
  (`test signaling-group N`, `display errors`, `H323-SGR`/`MEDPRO` entries). On the test stand the cause was media resources not enabled on CM.
- Developer tests: `make test` (unit tests on vectors from the captures), `make asan`, `make tsan`, `make fs-syntax` (syntax check of the FreeSWITCH glue against our own stubs).
